# Handover (first written 19 Oct 2026, updated 4 Nov 2026)

A new session reads this file, then CLAUDE.md. The product is complete and live; what follows
is the state, what the owner still has to do, and the ideas left for later.

## Working copy and deploys

- Work happens in the worktree `/root/Projects/football-league-ui` on branch `claude/ux-game`;
  the main checkout `/root/Projects/football-league` is an older `master` (it cannot check out
  `claude/ux-game` while the worktree has it). Run `git status` first: another session may have
  left uncommitted work (it happened on 18 Oct).
- Ship = `git push origin claude/ux-game:master` after a green Check (owner's standing go since
  5 Oct). A change to layout or data: run Tour on the branch too
  (`gh workflow run tour.yml --ref claude/ux-game`) and look at a few cropped shots first.
  `firestore.rules` changes deploy from `master` by themselves (`firebase.yml`; a dry run on
  other branches).
- The LXC is weak: no builds, emulator or Playwright locally; everything runs in CI. Add a
  dependency with `npm install --package-lock-only <pkg>@<version>` (no node_modules here).
- Production writes beyond the rules need the owner's credentials: he runs scripts in Google
  Cloud Shell (console.cloud.google.com → `>_`, `git clone` / `git pull` of the public repo) with
  `--token "$(gcloud auth print-access-token)"`. Reading production now needs an account too
  (an anonymous token from Identity Toolkit `accounts:signUp` with the app's public API key reads
  what any visitor may).

## State (`master` a6a53b6, all green)

- UI/UX redesign "Nocą" with 21 rounds of independent design evaluation, closed by the owner on
  19 Oct (`docs/superpowers/reviews/`; rulings in `evaluations.md`).
- Data per league (`GameService`, `TournamentService`: one listener per league); "your leagues"
  = the device's leagues (`league/device-leagues.ts`). Players and the user's leagues are
  whole-collection / per-account listeners.
- 2017 migration done (19 Oct): every game has `league`; `currentLeagueId()` maps `legacy`.
- Accounts (24–25 Oct): every visitor is signed in anonymously (`shared/auth.service.ts`); Google
  sign-in by popup links that account (`shared/account.component.ts`: the player in their kit,
  the e-mail, sign in/out; in the ☰ menu and the rail). A Google account claims its player
  (`players/{id}.uid` with `users/{uid}.player`, one batch); only the owner dresses them; a
  claimed player is nobody else's. Every write needs an account.
- Leagues: `owner` and co-owners `admins` run them (settings, delete, restore, erase for good);
  private to `members`; others join by `#/l/<id>?invite=<code>` ("Zaproś" opens a QR code,
  `league/invite-dialog.component.ts`). Leagues without `members` are from before and stay open
  until taken ("Zostań właścicielem"). Archived leagues are folded apart on the leagues page and
  carry a padlock in the rail; deleted ones have their own page `#/leagues/deleted` (a quiet
  link at the bottom of the leagues page).
- E2E sign-in uses an emulator-only hook (`flSignInForTests` in `AuthService`); rules are tested
  in `e2e/tests/rules.spec.ts` with Auth emulator tokens.
