# UI „Nocą” — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every existing screen the look the owner chose ("A. Stół nocą"): a dark table at night, LED dot-matrix numbers, the green felt and the yellow ball, without changing what the screens do.

**Architecture:** The look already lives in tokens (`--fl-*` in `src/styles.scss`, with Angular Material's `--mat-sys-*` mapped onto them) and in component styles that read those tokens. This phase rewrites the tokens for a single dark scheme, swaps the fonts (Archivo for text and headings, Doto for numbers), adds three shared utilities (`.fl-led`, `.fl-board`, `.fl-felt`) and then restyles the components screen by screen. Templates change only where a number needs the LED class or a surface needs the felt/board class. No routing, data or behaviour changes.

**Tech Stack:** Angular 22 (standalone components, SCSS), Angular Material 22 tokens, Fontsource (`@fontsource/archivo`, `@fontsource/doto`), Transloco texts unchanged.

**Spec:** the owner's choices on the redesign canvas https://claude.ai/artifact/As2G6VoRzAPeEkLxmbC8Kx (page "Eksploracja stylu", row "A. Stół nocą, runda 3", and the page "Flow aplikacji" for every screen in that style). Order agreed with the owner on 5 Oct 2026: first the UI (this plan), then the UX (navigation and screen structure from the "Flow aplikacji" page), then new features (kits, sign-in) on top.

## Global Constraints

- Look only: no change to routes, data, Firestore writes, texts or what a tap does. UX changes from the prototype (league tab "Liga", the "+" sheet order, landscape game views, kits, accounts) belong to the next phases.
- Keep every class name, element and ARIA attribute the e2e scenarios use (`e2e/tests/*.spec.ts`), e.g. `header.top .bug`, `header.top button.more|detail`, `footer.bar`, `button.goal`, `nav.tabs button.play`, `fl-game-list a.game .score`, `.fl-tiles`, `.fl-records dt`, `table.table tr.first`, `.note`, `.deleted-note`, `.vs`, `p.score`, `p.meta`, `main .hero`, `.card.series`.
- One dark scheme: `color-scheme: dark` for the whole app. A light variant may come back later through the same tokens.
- Palette (exact): page `#000000`, card `#0B0C0D`, card-2 `#17191C`, dialog `#16181A`, sheet `#121416`, line `#232623`, ink `#F2F4F0`, ink-2 `#9AA39D`, ball `#FFC629` on `#1B1410`, felt `#157A42 → #0D5A31 → #083D21`, board `#0A0B0A` with 5 px dots `#1C1E1C`, team fills red `#D0433A` / blue `#3A64D6` (white text), team text and LED red `#FF5A4E` / blue `#5C8CFF`, win `#5BE394`, loss `#FF8A80`.
- Fonts: Archivo 400/500/600/700/800 for all text; headings sentence case, no italics, no forced capitals. Doto 900 (LED) only for numbers of about 18 px and more (scores, Elo, times, tallies, tiles, records, ranks); smaller numbers stay Archivo with tabular figures.
- Fonts are self-hosted through Fontsource like today (prefer established libraries).
- Contrast: text at least 4.5:1 (3:1 from 24 px), touch targets at least 44 px, `prefers-reduced-motion` respected.
- The owner's machine is too weak for builds: no `npm ci`, `ng build`, Playwright or emulator locally. Verification is the Check workflow on the pushed branch (unit tests, `ng build -c production,emulator`, Playwright scenarios with screenshots). Dependencies change with `npm install --package-lock-only`.
- Never push to `master`; merging is the owner's production deploy.

## Review Focus

- Long player names and three-digit scores in the game cells and the LED scoreboard: they must not overflow or overlap the swap buttons (check the `game-running`, `game-rotated` and `game-finish` screenshots).
- Material components on a dark page (dialog form fields, autocomplete panels, chips, slide toggles, menus, snackbars): text and outlines must stay readable (check `tournament-new-*`, `tournament-edit`, `tournament-delete` screenshots).
- brackets-viewer on a dark page: its own CSS variables must be set, or the bracket shows white boxes (check `cup-start`, `cup-won`).
- Charts (Chart.js) read token colours at runtime (`shared/css-color.ts`): "ink" is now light, so grid lines and the highlighted line must still read on black (check `stats-league-elo`, `stats-profile`).
- Doto at small sizes: only use `.fl-led` from about 18 px; check that rank numbers, tallies and the countdown stay legible.
