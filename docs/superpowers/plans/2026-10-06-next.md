# Next increments (living plan)

Kept up to date after every increment, so a new session (or one after the context runs out)
can pick up where the last stopped. Read this file first, then CLAUDE.md's latest owner
round.

## How the owner wants us to work (6 Oct 2026)

- Larger UX changes: design first on the canvas (https://claude.ai/artifact/As2G6VoRzAPeEkLxmbC8Kx,
  one page per round, e.g. "Runda 4"), check the design is right and useful, then build.
- Build in small commits on `claude/ux-game`; each push runs the Check workflow (unit tests,
  production build against the emulator, Playwright scenarios on a Pixel 7 with screenshots).
- When Check is green, fast-forward `master` (`git push origin HEAD:master`): that deploys to
  GitHub Pages. The owner allows this for finished, green work; rules changes still need a
  word to him first.
- After each increment: look at the screenshots (`gh api .../actions/runs/<id>/artifacts`,
  then the `e2e` zip; see the memory note on CI screenshots), review critically (scales to
  thousands of users? no bordered marking? is the UX clear?), then plan the next increment.
- Never run the emulator, builds or Playwright on the owner's machine (an LXC); CI does it.
